Built-in `batch`, `edit`, `multiedit`, `edit_lines`, `insert_lines`, and `grep` schemas now reject unknown properties with `additionalProperties: false`. Optional fields use nullable types and `edit`/`multiedit` no longer require `new_string`, so deletions are explicit and invalid keys like `command`, `tool_uses`, or `recipient_name` are caught before dispatch. The tool `strict` flag is now wired through to providers that support grammar-constrained tool calls.
